# textuniq

Повышение уникальности русских текстов в Word: каждый абзац отдельно проходит
цепочку перевода `ru → en → de → ru` (Яндекс Переводчик или локальные модели), затем
все виды тире заменяются на «-». Исходный файл не меняется, результат сохраняется
копией `<имя>_uniq.docx`.

## Установка

Нужен Python 3.10+.

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate

pip install -e ".[dev]"              # ядро + тесты (Яндексу ничего больше не нужно)
pip install -e ".[ml]"               # локальные модели: torch + transformers
```

Совет для Linux без видеокарты: сначала поставьте CPU-сборку torch, она намного легче:
`pip install torch --index-url https://download.pytorch.org/whl/cpu`.

## Настройка Яндекс Переводчика

Нужен API-ключ сервисного аккаунта в Yandex Cloud. Официальная инструкция:
https://yandex.cloud/ru/docs/translate/quickstart

1. Войдите в консоль https://console.yandex.cloud под своим Яндекс ID.
2. В разделе «Биллинг» создайте платёжный аккаунт и привяжите карту; статус должен
   быть ACTIVE. Стартового гранта для новых клиентов сейчас нет, оплата с первого символа.
3. В каталоге (подойдёт `default`) создайте **сервисный аккаунт** и назначьте ему роль
   `ai.translate.user`.
4. Откройте сервисный аккаунт → «Создать новый ключ» → **API-ключ**, область действия
   `yc.ai.translate.execute`. Скопируйте секрет сразу: он показывается один раз.
5. Положите ключ в файл `.env` в папке, откуда запускаете программу (шаблон — `.env.example`):
   ```
   YANDEX_API_KEY=ваш-ключ
   ```
   Или задайте переменную окружения: `export YANDEX_API_KEY=...` (Linux/macOS),
   `$env:YANDEX_API_KEY="..."` (PowerShell). Файл `.env` в git не попадает.
   `YANDEX_FOLDER_ID` нужен только при работе от пользовательского аккаунта; для
   API-ключа сервисного аккаунта его не указывают.
6. Проверка: `textuniq text "Утро — лучшее время для бега." --engine yandex`.

Стоимость: около 500 ₽ за 1 млн символов (с НДС). Документ на 2–3 страницы — это примерно
15–18 тыс. символов за три перевода цепочки, то есть около 8–9 ₽. После каждого запуска
программа печатает, сколько символов отправлено и примерную стоимость по тарифу
(тариф зашит в `yandex_api.py`, сверяйте с актуальным).

Абзац отправляется целиком (лимит запроса — 10 000 символов). При ошибке ключа или прав
программа сразу останавливается; при временных сбоях (429, 5xx, сеть) повторяет запрос.

## Запуск

```bash
# обработать документ (по умолчанию движок marian)
textuniq doc samples/sample_article.docx --show

# прогнать по цепочке произвольный текст — удобно для быстрых экспериментов
textuniq text "Утренний бег — это простой способ улучшить самочувствие."

# другой движок / другая цепочка / строго офлайн
textuniq doc статья.docx --engine yandex --show
textuniq doc статья.docx --engine nllb
textuniq doc статья.docx --chain ru,en,ru
textuniq doc статья.docx --offline
```

Без установки как пакета: `python -m textuniq ...` из папки `src`.

`--show` печатает каждый абзац «было / стало», чтобы глазами оценить результат.
`-v` дополнительно показывает промежуточные переводы на каждом шаге цепочки.

Локальные модели при первом запуске скачиваются в кэш HuggingFace (`~/.cache/huggingface`),
нужен интернет. Дальше они работают офлайн; `--offline` запрещает любые обращения в сеть.

## Движки перевода

| Движок | Модели | Лицензия | Комментарий |
|---|---|---|---|
| `marian` (по умолчанию) | OPUS-MT: `opus-mt-ru-en`, `opus-mt-en-de`, `opus-mt-tc-big-de-zle` | CC-BY 4.0 | Отдельная модель на каждую пару; быстрые. Прямой модели de→ru нет, используется de→восточнославянские с токеном `>>rus<<` |
| `nllb` | `facebook/nllb-200-distilled-600M` (меняется через `--model`, напр. `...-1.3B`) | **CC-BY-NC 4.0, некоммерческая** | Одна модель на все направления, тяжелее |
| `yandex` | Яндекс Переводчик (Translate API v2) | условия Yandex Cloud | Облако, платно. Нужен интернет и API-ключ |
| `identity` | — | — | Ничего не переводит, только чистит тире. Для отладки работы с docx |

Новый движок добавляется в `infrastructure/translators/` и регистрируется в `factory.py`.
Если у переводчика есть лимит длины текста, он объявляет его атрибутом `max_text_chars`.

## Что именно обрабатывается

- **Переводится** каждый абзац основного текста: обычные абзацы, заголовки, пункты
  списков, ячейки таблиц (в том числе вложенных), надписи.
- **Только замена тире**: колонтитулы, сноски, примечания.
- Абзацы без букв (числа, пустые строки) не переводятся.
- Тире: все символы Unicode-категории «Pd» (—, –, ‒, ―, ‐, ‑ и т.д.) плюс знак минуса `−`
  превращаются в `-`. Замена делается **после** перевода, иначе модели вернут тире обратно.
- Для локальных моделей длинный абзац режется по предложениям на куски до 600 символов
  (`--max-chunk`) — ограничение моделей. Куски одного абзаца не смешиваются с другими
  абзацами. В Яндекс абзац уходит целиком.
- Форматирование: при замене тире оно сохраняется полностью. При переводе весь текст
  абзаца попадает в первый фрагмент, поэтому выделения внутри абзаца теряются.
  Стиль абзаца, списки и картинки остаются.

## Архитектура

```
src/textuniq/
  domain/            чистые правила без внешних зависимостей
    models.py        TextBlock, BlockRole, TranslationChain
    dashes.py        нормализация тире
    text.py          что переводить, разбиение на предложения
    errors.py
  application/       сценарии и порты, не знают про docx и torch
    ports.py         Translator, EditableDocument, DocumentLoader
    translation.py   ChainTranslator (цепочка языков), SegmentingTranslator (разбиение длинных абзацев)
    processing.py    BlockProcessor: перевод + правила очистки для одного абзаца
    uniquify.py      UniquifyDocument: открыть → обработать абзацы → сохранить копию
    output_path.py
  infrastructure/    адаптеры к внешнему миру
    docx_document.py чтение/запись .docx на уровне XML-абзацев
    translators/     marian, nllb, yandex_api, identity + фабрика
  interfaces/        командная строка (cli.py) и загрузка .env (env_file.py)
  bootstrap.py       корень композиции: собирает слои по настройкам
```

Зависимости идут только внутрь: `interfaces → bootstrap → application → domain`,
`infrastructure` реализует порты `application`. Будущий веб-сервис станет ещё одним
модулем в `interfaces/` и будет использовать тот же `bootstrap.build_uniquify`.

## Тесты

```bash
pytest                 # всё, кроме тестов на настоящих моделях
pytest -m models -s    # прогон настоящих моделей (скачает их при первом запуске)
```

- `tests/unit` — домен, прикладной слой и адаптер Яндекса на фейках.
- `tests/integration` — работа с реальными .docx (таблицы, колонтитулы, сноски, надписи,
  картинки); адаптер Яндекса против локального HTTP-сервера, имитирующего API;
  адаптеры transformers на крошечных случайных моделях, собранных на лету без интернета
  (эти тесты пропускаются, если не стоит `.[ml]`).
- `tests/acceptance` — три критерия приёмки из ТЗ на моковом документе и CLI.
- `tests/models` — проверка, что настоящие модели возвращают русский текст.

Домен, прикладной слой, docx-адаптер и адаптер Яндекса написаны через TDD:
сначала тест, потом код.
Адаптеры нейросетей — тестами по ходу, так как их API пришлось сначала исследовать.

Моковый документ: `samples/sample_article.docx`, пересобирается командой
`python scripts/make_sample.py`.

## Известные ограничения метода

- Через английский теряются «ты/вы» и род («я сделал/сделала»): цепочка может их перепутать.
- Имена собственные, термины и ссылки модели могут исказить.
- Короткие простые фразы часто возвращаются почти без изменений.
